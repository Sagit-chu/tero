# 进度更新 (2026-05-12)

## 已完成的重构与功能

1. **从 npm 迁移至 pnpm**
   - 更新了 `frontend` 和 `e2e` 的依赖管理，删除了 `package-lock.json` 并生成了 `pnpm-lock.yaml`。
   - 修改了根目录下的 `README.md`，将所有的启动、测试命令更新为 `pnpm` 语法。

2. **修复监控循环 (MonitorService) 的硬编码状态**
   - 解决了前端 `Flvx Node Status` 永远显示 "Alive" 的问题。
   - 引入了 `No Active Node` 的真实状态展示。
   - 后端增加线程安全的状态暂存（`lastStatus`），并通过 `api/status` 暴露给前端。

3. **适配真实的 Flvx 面板架构 (基于隧道及节点的监控和替换)**
   - **Flvx Client 更新**: 
     - 实现了真实基于 Token 的 `Login` 并维持 Token 刷新机制。
     - 增加了获取节点列表 (`GetNodes`) 和获取隧道列表 (`GetTunnelsRaw`) 的 API 方法。
     - 实现了更新指定隧道的入口节点信息 (`UpdateTunnel`)。
   - **后端数据库与仓库层更新**: 
     - 扩展了 SQLite 数据库的 `nodes` 表，增加了 `flvx_node_id` 和 `flvx_node_name`，以便将本地的备用节点直接关联到 Flvx 面板中的真实节点。
     - 更新了 `NodeRepository` 的各项 CRUD 逻辑，并在 `/api/nodes` 接口中暴露给前端。
   - **监控与自动替换逻辑重构**: 
     - `MonitorService` 不再仅仅测试本地数据库的“Active”节点。
     - 现在系统从配置中读取要保护的 `flvx_tunnel_id`。
     - 每轮周期调用 Flvx API 获取该隧道的详情，从中解析出当前的入口节点 (`inNodeId[0].nodeId`)，并在所有的 Flvx 节点中查找到该节点的真实 IP 并在本地进行 Ping 和 GFW 检测。
     - 当检测到宕机或被墙时，系统从本地的 Standby 池中取出一个包含可用 `flvx_node_id` 的备用节点，通过修改隧道的 `inNodeId` 调用 `UpdateTunnel` 进行替换。
